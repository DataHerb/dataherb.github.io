Know which pipelines are healthy.
  • Every job (Airflow, GitHub Actions, cron) writes a small JSON status file with dataherb status emit.
  • The site shows what is failing, stuck or stale, live, without a backend.
  • dataherb status check exits non-zero in CI when a job is unhealthy.
No server, no database.
  • A scheduled GitHub Actions job rebuilds the site with dataherb catalog build.
  • Data is served straight from S3, git or the site itself.
  • Datasets are added, changed and reviewed through pull requests, validated and linted in CI.
